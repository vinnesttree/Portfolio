# Portfolio

Personal portfolio site for Alex Roeser. It shows GitHub projects with live repository data and LinkedIn content (experience, education, publications, posts, articles). It's a static site served by nginx from a small, non-root Docker container.

- **No build step and no runtime dependencies.** Plain HTML, CSS and JavaScript. All content lives in three JSON files.
- **Live GitHub data.** Each project card shows its language, stars and last-updated date from the public GitHub API. New public repositories appear automatically under *More on GitHub*. Private repositories are never shown.
- **LinkedIn import.** A zero-dependency script turns your LinkedIn data export into site content. Sections without content stay hidden.
- **Light and dark themes**, responsive down to phone width, with accessible colour contrast.

## Run it with Docker

```sh
docker compose up -d --build
```

Then open <http://localhost:8080>. To use another host port, run `PORT=80 docker compose up -d`.

Without Compose:

```sh
docker build -t portfolio .
docker run -d --name portfolio -p 8080:8080 --restart unless-stopped portfolio
```

The container:

- runs nginx as an unprivileged user on port 8080, from `nginxinc/nginx-unprivileged:1.30-alpine`
- sends security headers (CSP, `nosniff`, frame denial and a referrer policy) and gzips text assets
- exposes `/healthz` for the Docker health check
- runs read-only with all Linux capabilities dropped under Compose

### TrueNAS with Dockge and Nginx Proxy Manager

Every push to `main` publishes a ready-built image to `ghcr.io/vinnesttree/portfolio:latest`, using the GitHub Actions workflow in `.github/workflows/container-image.yml`. Dockge on TrueNAS can run that image directly, with Nginx Proxy Manager in front for HTTPS. Updating the site is then a push followed by Dockge's **Update** button. The step-by-step guide is in [docs/truenas-dockge.md](docs/truenas-dockge.md).

### HTTPS and a domain

The container serves plain HTTP, so put it behind whatever already terminates TLS on your server (Nginx Proxy Manager, Caddy, Traefik, nginx or Cloudflare). For a single server without a proxy yet, Caddy can fetch certificates automatically. Add this to `docker-compose.yml`, replacing the domain with yours, and point the domain's DNS at the server:

```yaml
  caddy:
    image: caddy:2-alpine
    command: caddy reverse-proxy --from aroeser.com --to portfolio:8080
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - caddy_data:/data
    restart: unless-stopped

volumes:
  caddy_data:
```

## Editing content

Everything on the page comes from `site/content/`:

| File | What it holds |
| --- | --- |
| `profile.json` | Name, headline, about text, links, skills, and optionally `email`, `location` and `resume` (for example `"assets/resume.pdf"`). Empty fields are hidden. |
| `projects.json` | The featured projects: GitHub repo name, tagline, summary, highlights, specs, tags and extra links. `showOtherRepos` lists your remaining public repos automatically. `exclude` hides repos by name. |
| `linkedin.json` | Generated by the LinkedIn importer, or edited by hand. |

Rebuild after editing (`docker compose up -d --build`). While editing, you can instead uncomment the `volumes:` lines in `docker-compose.yml` so changes show on refresh without a rebuild.

To add a project photo, put the image in `site/assets/img/` and give the project an `"image"` path and an `"imageAlt"` description.

Preview without Docker by serving the `site/` folder over HTTP, for example `python3 -m http.server 8000 --directory site`. Opening `index.html` directly from disk doesn't work, because browsers block loading the JSON files from `file://`.

## Adding your LinkedIn content

LinkedIn has no public API for profiles or posts, and it blocks automated access to profile pages. Instead, the site imports the data export LinkedIn gives you:

1. On LinkedIn, go to **Settings & Privacy → Data privacy → Get a copy of your data**. Choose the larger archive, not the quick one: posts and articles are only in the larger one. LinkedIn emails you when it's ready, which can take up to a day.
2. Unzip it into a folder named `linkedin-export/` in this repository. It's git-ignored, so it can't be committed by accident.
3. Run the importer, using Node 18+ or Docker:

   ```sh
   node scripts/import-linkedin.mjs linkedin-export
   # or, without Node installed:
   docker run --rm -v "$PWD":/work -w /work node:22-alpine node scripts/import-linkedin.mjs linkedin-export
   ```

4. Check the summary it prints, then rebuild the container.

The importer reads only the sections the site shows: profile headline, about and location, positions, education, projects, publications, posts, articles, certifications, honors, volunteering, skills and languages. It never touches messages, connections, contact details or anything else in the export. Your LinkedIn headline and about text replace the defaults in `profile.json`.

**Posts are published only if LinkedIn marks them as public.** The importer prints how many posts it found for each visibility value, and how many it published or skipped. If public posts were skipped because LinkedIn labels them differently, re-run with `--visibility <VALUE1,VALUE2>`, or use `--all-posts` to publish everything. Reposts that have no text of your own are always skipped.

Other options: `--dry-run` prints the summary without writing anything, `--include-drafts` keeps articles that look unpublished, `--out <file>` changes the output path, and `--handle <name>` sets your LinkedIn handle (default: `aroeser2`).

## Tests

```sh
npm test
```

The tests cover the LinkedIn importer: CSV parsing, date formats, field mapping, the visibility filter, articles, and that private files in an export are never read. They use the synthetic export in `scripts/test/fixtures/`.

## Layout

```
Dockerfile, docker-compose.yml   Container image and run configuration
.github/workflows/               Tests, then builds and publishes the image to GHCR
docs/truenas-dockge.md           Hosting guide: TrueNAS + Dockge + Nginx Proxy Manager
nginx/default.conf               Server config: headers, caching, health check
site/                            Everything that gets served
  index.html, 404.html
  content/                       profile.json, projects.json, linkedin.json
  assets/css, assets/js, assets/img
scripts/import-linkedin.mjs      LinkedIn export → site/content/linkedin.json
scripts/test/                    Importer tests and fixtures
```
